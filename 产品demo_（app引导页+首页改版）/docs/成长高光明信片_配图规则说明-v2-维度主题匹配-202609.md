# 成长高光明信片配图规则 v2 · 维度—主题—归属场景匹配

版本：2026-09-07
定位：**本文是成长高光明信片配图的唯一完整规则**，覆盖提示词判定、图库分层与标签、画面细则、选图算法、提示词补丁与验收点。


---

## 0. 一句话讲明白配图规则：

会话单选「维度 + 主题 + 场景」；
图片多打「维度 + 主题 + 场景」。
硬召回只要维度和主题命中；场景用来收窄；
再优先排除该账号最近 7 次用过的；
如果候选图都用过，选择最久未使用的图，并列时随机，最后锁图。

## 1. 三层分工与规则总览

| 层 | 回答什么 | 会话侧（提示词输出） | 图库侧（打标） | 选图角色 |
| --- | --- | --- | --- | --- |
| 高光维度 | 为什么值得记录 | 单选 1~6 | `dimension_ids` 可多个 | **硬召回** |
| 高光主题 | 这一刻是什么成长 | 单选 43 之一 | `highlight_themes` 可多个 | **硬召回** |
| 归属场景 | **高光那一刻**发生在什么生活语境 | 单选 8 类之一，或 `unknown` | `content_scenes` 可多个；通用图打「通用」 | **有则用，无则回退** |

**匹配标签 = 维度 + 主题（+ 场景）。** 维度和主题是硬召回，场景的图持续补充，场景作为优先使用的标记。

## 4. 图库设计：分层、打标与图片画面

### 4.1 素材库分层（两层）

| 层 | 内容 | 关键字段 | 存储 |
|---|---|---|---|
| **文件层** | 每个素材的图片 / 视频文件本身 | `oss_url` | OSS：`growth_postcard/{id}.{ext}` |
| **标签层** | 素材元数据与匹配标签（见 §4.2） | `id`、`oss_url`、`asset_type`、`dimension_ids`、`highlight_themes`、`content_scenes` | 业务数据库素材表 |

**入库流程：**

1. 图片 / 视频上传 OSS，获得唯一 `oss_url`。
2. 业务库创建素材记录，写入 `id`、`oss_url`、`asset_type=growth_postcard`。
3. AI 批量预标注 + 人工校验，打齐 `dimension_ids`、`highlight_themes`、`content_scenes`。

选图只查标签层，取文件时才用 `oss_url`。

**历史明信片与素材替换（产品已定）：** 每条高光 / 明信片在选图成功后写入当时选中的 `oss_url`；展示只读这条地址，OSS 上当前是什么文件就展示什么图。同路径覆盖文件时历史跟着变，本版接受，不要求 `asset_version` 或文件快照。想让历史不变，必须上传新文件 / 新 `oss_url`。只改标签不影响已落库记录。详见《功能需求PRD》§4.8.1。

### 4.2 图片如何打标签（`asset_type = growth_postcard`）

#### 打哪些标签

一张图对应素材表里一条记录。除了 `id` / `oss_url`，**只打三组匹配标签，每组都可以有多个值**：

| 字段 | 必填 | 取值 | 一张图能打几个 | 作用 |
|---|---|---|---|---|
| `dimension_ids` | ✅ | 1~6 | **可多个** | 硬召回 |
| `highlight_themes` | ✅ | §2 的 43 个主题名，逐字一致 | **可多个** | 硬召回；覆盖率来源 |
| `content_scenes` | ✅ | §3.1 的 8 类；画面没有生活道具则打「通用」 | **可多个** | 场景收窄：命中则进入池 B |

「通用」是图库专用值，会话侧不会输出它，因此**通用图永远不会在场景这一步被命中**，它靠「无场景命中时回退硬召回全池」进入候选（见 §5.3）。


#### 图和标签是多对多的

这是本规则的核心机制，也是图库不需要做到 43 张起步的原因：

- **一张图 → 可多个主题**：画面画的是「递出去」这个动作，那么分享、帮助、合作都说得通，三个主题全打上。这张图就同时进了三个主题的候选池。
- **一个主题 → 可多张图**：同一个主题会被很多张图打上，它们共同组成该主题的候选池，选图时再靠场景和去重从中挑一张。
- **会话侧永远是单选，图库侧永远可多值。** 选图就是拿会话的那一个值，去匹配图片的值集合，**命中（属于集合）即进入候选**，不算相似度、不打分。


#### 打标原则与运营约束

- **说得通的标都打上，不要只打最像的那一个。** 一张图正常打多个主题；
- **覆盖率保证：** 每个已上线主题至少有 1 张图打上该主题（靠一图多主题摊薄，不必一主题一张）。硬召回为空说明图库缺这个主题，走补图，**不能靠改场景或改主题硬凑**。

### 4.3 图片画面硬规则（要点）

风格固定为单一方向，不做多风格并行：

- **图片风格**：皮克斯式 3D 温暖插画，圆润体块、柔和全局光、轻微边缘光，亲和、儿童向，不做锐利写实。@设计师定
- **全部主题、全部场景共用同一风格与调色**，不设 `style` 字段。此前水彩隐喻维度图是另一个风格方向，v2 不再沿用。
- **主角只能是空镜头或 Lukie**，禁止写实儿童的五官、发型、肤色。
- **通用图不放场景道具**，只保留成长姿态 + 空 / Lukie；当前图库以通用图为主。
- **第二个人只分体型，不分身份**：一大一小 = 家人，两个接近体型 = 同伴。不画爸爸 / 妈妈 / 爷爷的脸，身份由标题和原话承担。
- **场景靠类别道具表达**：每张 1～3 个，不超过画面约三分之一；不用专名，画面不含文字、字母、logo、可辨认 IP。
- **主题数 ≠ 图片数**：图片量靠载体、构图、氛围变体扩展，不靠拆主题。覆盖 43 个主题。

建图按素材层级持续补充，不绑定版本阶段：

- **基础覆盖 · 通用**：图多为通用画面，`content_scenes` 打「通用」，主角空或 Lukie，每个主题至少 1 张可命中的图。提示词同时输出 `content_scene`；当场景图尚未补齐时，选图主要走「维度 + 主题 → 最近 7 次未使用优先 → 最久未使用兜底」。
- **场景扩充 · 精准**：按真实会话频率持续补场景变体，优先 **游戏娱乐（含音符 / 音箱）** 和 **家庭陪伴**；同一主题下换场景道具，不乘「爸爸 / 妈妈 / 爷爷」三套图。只做到归属场景粒度，不做具体对象精排，也不做昼 / 夜。素材扩充不改变选图算法（见 §5.3）。

## 5. 选图规则

```text
对话内容
── 提示词侧（单选）──
↓ 判定高光（score≥7 且风险等级不是高风险 / 紧急，见 §5.1）
↓ 识别高光选图信息：dimension_id + highlight_theme + content_scene（8 类或 unknown）
── 后端侧──
   ↓ 硬召回：dimension_id 命中 AND highlight_theme 命中 → 池 A
   ↓ 场景：A 中 content_scene 命中 → 池 B；B 为空或 unknown → 回退用 A
   ↓ 去重：当前池去掉该用户最近 7 次用过的 → 池 C；C 非空则池内随机
   ↓ C 为空 → 在去重前的当前池中选最久未使用的图，并列时随机
   ↓ 按 session_id 锁图
```

### 5.1 高光判定与选图（调整：风险等级和高光的影响）

**是否高光由后端工程按下式计算；选图是高光成立后的独立链路。** 提示词只负责产出 `highlight_score` 和 `risk_judgement`，不输出高光结论。风险按等级分级，不再用 `is_hit` 一刀切：

```text
has_highlight = highlight_score >= 7
                AND risk_judgement.level ∉ {高风险, 紧急}
```


| `risk_judgement.level` | 是否算高光 | 理由 |
|---|---|---|
| 空（未命中） | 是，创建选图任务 | — |
| 需关注 | **是，创建选图任务** | 厌学、友谊烦恼这类日常度高，一刀切会让这类孩子长期收不到明信片 |
| 高风险 / 紧急 | **否，不创建选图任务** | 家长此时会收到风险提醒，不应同时弹一张轻量正向卡片稀释严肃性 |

- **这里的 `risk_judgement` 是会话级字段，每段会话各判各的**，和首页高危模块用的日级汇总结果（日级 `is_hit` 取当天所有会话的 OR、`level` 取最高）不是同一个东西。同一天里既有会话命中高风险 / 紧急、又有别的会话正常创建选图任务，是正常状态；**不要用日级风险去拦截当天的选图**。
- 判定为高光 → 创建选图任务；不是高光 → 不创建任务、不写图片使用记录。
- **不影响成长时刻**：成长时刻有会话即有，与是否高光、选图结果无关（见《功能需求PRD》§4.7）。
- 选图服务失败属于技术异常，**不改变「这是一条高光」的判定**；该高光仍进入列表和详情，详情展示无图失败态（见 §6）。
- **提示词只出数据，不出结论**：打分、标风险等级、给维度与主题与场景；不输出 `has_highlight`，不输出图片 ID，不参与选图。高光资格由后端按上式算出，LLM 没有裁量空间，也不应为了影响高光判定而调分。
- 6 分不算高光；7 分且风险等级不是高风险 / 紧急才算高光并触发选图。
- 主题必须落在对应维度区段内。不一致时**以 `highlight_theme` 名为准回正 `dimension_id`**（主题名唯一确定维度），照常选图，不跨维硬搜；只有主题名本身非法才不创建选图任务（见 §6）。

> ✅ 本条已同步到《功能需求PRD_Guide-and-Home-Page.md》§4.8.1（高光时刻定义改为「分数 + 风险等级」，且该字段由后端计算）与《会话级-洞察提示词_202608.md》（已移除 `has_highlight` 输出）。三处口径现已一致。

### 5.2 选图输入（提示词侧三字段）

后端选图只读 `highlight_info` 里的三个字段

| 字段 | 取值 | 在选图中的角色 |
|---|---|---|
| `dimension_id` | 1~6 | **硬召回** |
| `highlight_theme` | §2 的 43 主题之一，逐字一致（同时输出 `highlight_theme_id` 供区段校验） | **硬召回** |
| `content_scene` | §3.1 的 8 类之一或 `unknown` | 场景收窄，不阻断出图 |

- 三个字段**无论是否高光都输出**；未达高光时仅供抽检，后端不用它选图。
- **不输出**图片 ID、视觉方向、对象关键词、时段。后端也不把主题查表换算成视觉方向。
- `topic_tags`、`healing_quote`、`scene_hint` 不进入选图。
- 具体对象、事件时段、会话整体情绪都不是图片匹配字段。
- 字段缺失、非法或主题越出维度区段时的处理见 §6。

> 三个字段的完整定义、判定路径、典型表现、易混判例、JSON 结构与验收清单，见《会话级-洞察提示词_202608.md》。本文只约定「选图需要哪些输入、每个输入起什么作用」。

### 5.3 匹配优先级与回退

> **维度 + 主题（硬召回） ＞ 归属场景（有则用，无则回退） ＞ 最近 7 次未使用优先 ＞ 最久未使用兜底 ＞ 并列随机**

| 层 | 会话字段 × 图库字段 | 命中判定 | 是否限制候选 |
|---|---|---|---|
| **硬召回** | `dimension_id` × `dimension_ids`<br>`highlight_theme` × `highlight_themes` | 会话值 ∈ 图片值集合（主题名与 §2 逐字一致） | **硬条件**：不命中不能进入候选 |
| **场景** | `content_scene` × `content_scenes` | 会话值 ∈ 图片值集合；`unknown` 时跳过本步 | **有则用，无则回退**；不阻断出图 |
| **去重** | 该用户的成功使用记录 | 先检查候选 `image_id` 是否在最近 7 条里；若全部命中，再比较各图最后使用时间 | **有未使用则只用未使用**；都用过则选最久未使用，并列时随机 |

每一步都可以回退，但不能空窗：

| 情况 | 处理 |
| --- | --- |
| 硬召回为空 | 该主题图库缺口，记日志走补图；**不改用其他主题的图** |
| 有场景命中 | 只用命中场景的图 |
| 无场景命中 / `unknown` | 用硬召回全池 |
| 有最近 7 次未使用 | 只在未使用里随机 |
| 当前池都在最近 7 次里 | 在当前池里选最久未使用的图；多张同时并列时再随机 |
| 刷新 / 重试同一会话 | 不换图 |

当前图库多打「通用」场景，场景这一步通常不生效，链路等价于「维度 + 主题 → 去重 → 选图」；场景图持续补充后会自然生效。**通用图不会顶掉场景图**：只要有场景命中的图，本次就只在场景图里选。

### 5.4 使用记录与「最近 7 次」去重口径

- **按账号维度去重**：只看当前选图任务所属账号（`user_id`）的使用记录。一个账号对应一台 Lukie、一份宝贝档案，因此等价于按孩子去重，本期不引入独立的孩子标识。
- ⏳ 若后续支持一个账号绑多台设备 / 多份档案，去重维度需要下沉到设备或档案，届时同步修改本节。
- 按 `used_at` 倒序取最近 7 条**成功**使用记录（不足 7 条按现有条数）；候选 `image_id` 出现在这 7 条中即视为最近用过。不按自然日。
- 有最近 7 次未使用的候选图时，只在这些图中随机。
- 当前池的候选图全部出现在最近 7 条记录中时，查询这些候选图对该账号的最后成功使用时间，选择时间最早（即最久未使用）的图；多张并列时再随机。
- 所有随机选择均以 `session_id` 为种子，保证同一会话结果稳定，并锁定结果。

### 5.5 锁图

- 选图结果按 `session_id` 锁定：一张明信片绑定一段会话，业务库写入当时选中的 `oss_url`；首页 / 列表 / 详情只读该地址取图，**重试不换图、不回查标签层**。
- 同一段会话再次触发必须沿用已有结果。
- 同一账号多段会话偶发选到同一张图，本期可接受。
- 历史高光同样只认已落库的 `oss_url`。同路径覆盖文件时画面会变，本版接受；详见 §4.1。

**会话洞察结果一次性产出，同一段会话不重复分析**，因此不存在「事后改判」：分数、风险等级、维度、主题、场景以及后端据此算出的是否出片和选中的图片，都随首次结果固定。

> 同一段会话重跑 LLM，输出的措辞会有差异（大意相同），这也是不重跑的原因之一——重跑只会让家长看到的标题、总结和明信片发生无意义的变化。

### 5.6 兜底

- **运营保证每个已上线主题至少有 1 张可用图**（一图多主题可摊薄）→ 是高光且硬召回非空则必能选出。
- 硬召回因异常暂时无图，或图片资源加载失败 → 客户端展示内置占位图（见 §6），不改写选图结果、不新增使用记录。
- 本版不设独立「通用兜底图库」。通用能力 = 图打「通用」场景 + 主题覆盖。

### 5.7 一条高光如何匹配到一张图示例

以「孩子第一次和家人一起往前骑，虽然害怕但没有放弃」为例（画面不画真实小孩，不画成「爸爸脸」）：

| 步骤 | 结果 | 是否直接决定图片 |
|---|---|---|
| 1. 高光判定 | `highlight_score=8`、风险未命中 → 是高光，出片 | 决定是否出明信片 |
| 2. 判定维度 | `dimension_id=6` | 是，硬召回 |
| 3. 判定主题 | `highlight_theme=第一次做到` | 是，硬召回 |
| 4. 判定场景 | `content_scene=运动体能` | 否，收窄用 |
| 5. 硬召回 | 所有打了 D6 且含「第一次做到」的图 → 池 A | 是 |
| 6. 场景 | A 中打了运动体能的 → 池 B；没有则回退 A | 否 |
| 7. 去重 + 选图 | 最近 7 次未使用优先；全部用过时选最久未使用，并列再随机，最后锁定 | 得到 `image_id` |

## 6. 非法值与客户端资源异常

| 情况 | 处理 |
|---|---|
| `highlight_info` 或必填字段（`dimension_id` / `highlight_theme`）缺失、类型错误 | 不创建选图任务，记 `invalid_input`；不改变 `has_highlight`，高光仍可进入详情并展示无图失败态 |
| `dimension_id` 不在 1~6，或与 `highlight_theme` 所属维度不一致 | **以主题名为准回正 `dimension_id`**，记 `invalid_dimension`，照常选图 |
| `highlight_theme_id` 与 `highlight_theme` 指向不同主题 | **以主题名为准回正 id**，记 `invalid_theme_id`，照常选图 |
| `highlight_theme` 不在 §2 的 43 个主题内（自造、错字、非逐字一致） | 无法回正，记 `invalid_theme`，不创建选图任务；不改变 `has_highlight`，高光仍可进入详情并展示无图失败态 |
| `content_scene` 为空或非法 | 归一为 `unknown`，不影响选图，记 `invalid_content_scene` |
| 硬召回为空 | 记 `theme_pool_empty`，走占位图；同时进运营补图清单 |

**客户端资源异常：**
- 选图任务排队或进行中：高光卡照常出现，仅图片区加载中（首页轨道、列表、详情一致）；不改变 `has_highlight`。结束为成功则换真图，失败则无图失败态。页面停留期间图到了，原地替换，不把加载中写成占位图。
- 选图任务失败：按重试策略；超过上限标记 `failed`。不改变 `has_highlight`，高光仍进入列表和详情；图片区域展示无图失败态，不使用无关默认图。
- 已落库图片加载失败：客户端内置占位图，不改写结果、不新增使用记录。
- 占位资源自身不可用：记 `default_asset_unavailable`，不使用未知图片替代。

查收与进行中的衔接见《功能需求PRD》§4.8.4：进行中不进未读；进首页时已有未读真图才演仪式；人已在首页看加载中时图到了就原地换，不补演拆封。
