# Lukie App 引导、首页与「我的」改版功能需求 PRD

版本：2026-08-28
用途：供研发、设计、测试实现本版能力。界面布局、动效及最终文案以设计稿 / 原型为准；本文约定功能边界、状态判断、数据口径和跳转规则。

## 1. 需求目标与范围

本版围绕以下需求完成改版：

1. **前置引导**：新用户从启动 App 到进入首页的首次引导可完整走通，包含注册、设备激活和交接仪式等步骤。
2. **新手引导**：增加 7 个步骤的新手指引，并支持示例态首页模块讲解。
3. **首页**：完成头图、最近对话、使用指南推荐卡、今日总结、成长时刻和成长高光明信片等模块的展示与状态改版。
4. **「我的」**：收口一级入口，承载宝贝档案、系统设置、使用指南和帮助内容。

本文约定各模块的产品边界、状态判断、数据口径和跳转规则；图库标签和选图细则沿用对应配图规则。


### 1.2 本版不改

- iluki / Lukie 既有注册登录协议、原国内外版本有的注册和登录方式。
- 高危情绪的判断、生产和既有卡片样式。
- 今日情绪分、今日总结的文字内容生产规则；本版仅新增 / 替换今日总结配图来源与匹配规则。
- 对话时长、对话次数、对话标签等的技术侧 sql 统计工程不变
- 成长时刻的字段、音频和历史分页规则（单次条数沿用现网，下文记为 `XX`）。
- 高光时刻的评分、`has_highlight`、高光维度及风险判定的提示词规则等

### 1.3 国内外端 APP差异

## 3. 需求 1：前置引导

### 3.1 首次引导主路径

启动页 → 品牌欢迎页 → 家长 / 监护人身份确认 → 注册登录 → 家长授权 → 账号注册成功 → 设备联网（仅 Lukie）→ 6 位激活码 → 宝贝档案 → 交接仪式 → 新手指引 → 首页。

### 3.2 启动与欢迎

- 启动页使用 Logo。
- 品牌欢迎页使用慢动画展示。

### 3.3 注册、联网与激活

- iluki 与 Lukie 的注册登录分别对齐现网，本版不改登录协议。
- Lukie：账号注册成功后先进入连接 WiFi 页，再进入 6 位激活码页。
- iluki：无连接 WiFi 页，账号注册成功后直接进入 6 位激活码页。

### 3.4 宝贝档案（逻辑待定，和小智方沟通长记忆逻辑后补充）

- 全部字段均非必填。
- 一项都未填写时，「保存并继续」禁用；点击无效。
- 任意填写一项后，「保存并继续」可点；点击后保存已填内容并继续。
- 「先不填，和 Lukie 慢慢探索」始终可点；点击后不保存，直接进入下一步。
- 已保存内容必须落库，供「我的 - 宝贝档案」回显和再次编辑。
- 逻辑待定，和小智方沟通长记忆逻辑后补充。

## 4. 需求 2：新手引导

### 4.1 新手引导：出现与已读（方案待决策）

本节提供两种新手引导出现与已读方案，最终采用哪一种待领导决策。

#### 方案 A：简单方案（不区分，弹一次）

- 仅在 App 下载后的第一次打开，或 App 更新后有新引导的第一次打开时出现。
- 用户完整走完、点击「跳过」或点击右上角关闭，均记录为当前 App 版本已读；同版本后续不再出现。
- 已读状态按 App 版本记录；仅 App 更新且有新的引导内容时，才重新展示。

#### 方案 B：细致方案（区分完成、跳过、关闭）

- 新用户首次完成必要的注册、登录和设备激活流程后，首次进入首页时展示新手引导。
- 每套引导使用独立的 `guide_version` 标识，已读状态按账号和引导版本记录。
- 用户完整走完引导后，记录为 `completed`；当前引导版本不再主动展示。
- 用户点击「跳过」后，记录为 `skipped`；当前引导版本不再主动展示，但可从使用指南中再次查看。
- 用户点击右上角关闭或因异常中断时，记录为 `dismissed`；下次满足展示条件时继续展示，或从上次中断步骤继续。
- App 更新后，仅当 `guide_version` 发生变化且包含新增引导内容时重新展示。
- 同一账号在同一 `guide_version` 下最多主动触发一次，除非用户主动重新查看或产品配置重新触发。

### 4.2 新手引导：展示和结束

- 底图使用包含全部首页模块的有数据示例态（不使用真实数据），保证用户能看到完整模块讲解。
- 共 7 步，顺序为：自我介绍 → 唤醒方式 → 使用指南 → 关注提醒 → 今日情绪分和今日总结 → 成长高光明信片 → 成长时刻。
- 每步配置对应的形象图；当前步骤的目标模块滚动至可见区域并高亮。具体文案以原型为准。@设计师
- 完成、跳过或关闭后，立即退出示例态并进入真实首页，不保留任何示例数据。

## 5. 需求 3：首页

首页按模块组合，不为每种状态单独建设一套页面。先按当天真实数据确定页面状态，再套用各模块规则。

### 5.1 首页状态判断

| 状态 | 条件 | 页面表现 |
| --- | --- | --- |
| 新手引导中 | 满足 4.1 的展示条件，且用户尚未结束当前引导 | 展示包含全部首页模块的有数据示例态并叠加新手引导；示例数据不落库；引导结束后进入真实首页对应状态 |
| 首日仅有明信片 | 第一次绑定设备后的首日，且当天无对话 | 展示预设初见明信片；隐藏今日情绪分与今日总结；状态时刻和成长时刻使用空置态 |
| 日常无对话 | 非首次绑定首日，且当天无对话 | 头图和对话入口使用空置态；隐藏今日情绪分与今日总结；明信片展示无数据卡和最近 7 张；成长时刻展示今日空置卡并默认展开历史 |
| 有数据 · 有高危 | 当天有对话且命中高危 | 所有有数据模块按规则展示，包含高危模块 |
| 有数据 · 无高危 | 当天有对话且未命中高危 | 所有有数据模块按规则展示，不展示高危模块 |

### 5.2 首页头图（状态时刻 + Lukie 大头）

#### 5.2.1 展示规则

- 展示 Lukie 在线状态，口径与设备管理页一致。
- 右侧蓝色大头按分值档位（含空置档）10 个档位，匹配对应形象图；素材由设计提供。
- 当天无对话时，展示空置状态信息和空置大头。
- 当天有对话但 `daily_mood_score` 为 `null`（当天聚合结果无法评分）时，头图（状态时刻文案 + 蓝色大头）单独走 `null` 空置档「等待今日心情」；今日总结、成长高光明信片、成长时刻等其余有数据模块仍按有数据规则正常展示，不受头图空置影响。这种情况现状有需要技术解决同步问题；


#### 5.2.2 头图数据口径与文案规则

- `daily_mood_score` 由日级提示词产出，用于今日情绪分、今日总结和首页头图；`session_mood_score` 由会话级提示词产出，仅用于会话级洞察。
- 两者使用同一套分值档位。本版仅调整分段分值、档位状态及对应文案，不修改会话级、日级分数和总结等提示词的生产逻辑。
- 提示词不再输出 `mood_state`、状态时刻档位和陪伴文案；后端根据 `daily_mood_score` 查询配置表，返回状态档位 ID、状态名、文案和对应大头素材信息。
- 首页头图读取的 `daily_mood_score` 范围为 `0–100`；为 `null` 时进入独立空置档「等待今日心情」，不属于 `0–10` 分。
- 后端按 `daily_mood_score` 命中的状态档位，从每档 5 条候选文案中随机选取 1 条；随机仅发生在分数更新时，结果与分值、状态一并落库，刷新或重复进入首页不重新随机。
- 状态名和陪伴文案通过配置表维护，使用 i18n 文案 key；客户端仅展示后端返回结果，不自行分档、随机或翻译。
- 方案 A–E 的文案全部进入候选池，不预先固定某一套方案；具体分值区间、状态名和候选文案见下方「5.2.3 状态时刻文案配置」。

### 5.3 最近对话入口

- 仅国内 iluki 展示，海外 Lukie 不展示。
- 仅取最后一条对话的内容和时间；内容使用跑马灯完整展示。
- 时间：当天对话显示具体时间；昨天及更早显示对话日期。
- 当天无对话时不展示该入口。

### 5.4 使用指南推荐卡

- 默认展示。
- 点击「去查看」进入「我的 - 使用指南」网页版。
- 用户关闭后，该账号不再展示此首页推荐卡；未关闭则每次进入首页均展示。

### 5.5 高危情绪

- 仅当天有对话且命中高危时展示。
- 判断、数据生产和卡片样式沿用现有规则。

### 5.6 今日情绪分与今日总结

- 当天无对话时，两张卡片均不展示，直接从页面移除，不展示空卡。
- 当天有对话时，两张卡片均展示；文字内容生产规则沿用现网。
- 今日总结图片按下方配图规则返回；本版采用固定图片，后续再评估图库匹配。
- 话题标签支持点击，用气泡展示完整标签文字，格式为 `#标签名`。

**今日总结配图：**

**方案一｜固定图片（本版采用）：**

- 今日总结使用固定图片，不进行场景、时段、情绪或关键词匹配。
- 后端返回并持久化图片结果，客户端只展示，刷新不更换图片。

**方案二｜场景 + 时段选图（后续，图库齐备后启用）：**

- 待共享图库素材齐备，并达到场景 × 时段的覆盖要求后，复用成长高光明信片的基础选图框架。
- 今日总结只使用 `image_scene` 和 `event_period` 两个配图字段，不使用 `image_keywords` 做主体、事件和动作精排；选图任务和结果按业务类型独立持久化。

**建议：**

- 本版先采用方案一，优先完成固定图片和结果持久化；待素材齐备后，再评估切换到方案二。


### 5.7 成长时刻（原时光流）

- 内容展示沿用现有成长时刻结构；标题、总结、标签等由会话级提示词产出。
- 已生成成长高光明信片的成长时刻也必须保留在成长时刻列表中。
- 仅**已生成明信片**（选图 `succeeded`）的高光时刻可进入对应的明信片详情；普通成长时刻不可点击（没有详情页），但仍可播放音频。资格通过且输入合格后没有选不到图的情况；未生成明信片只可能来自资格不通过、输入不合格或服务失败。

**当天有成长时刻**：默认仅展示今日内容；末尾展示「上滑，继续浏览过往成长时刻」；上滑后按现网规则分页加载历史，减少请求压力。
**当天无成长时刻**：展示「今日空置无数据卡 + 过往成长时刻」，且过往内容默认展开，无需上滑操作。

### 5.8 成长高光明信片（图库匹配）

#### 5.8.1 概念与数据边界

| 名称 | 定义 | 是否每段会话都有 |
| --- | --- | --- |
| 成长时刻 | 原时光流卡片，包含标题、总结、原话、音频等现有内容 | 有会话即可有 |
| 高光时刻 | `highlight_score >= 7` 的成长时刻（与是否命中风险、是否出明信片无关） | 仅分数达标时有 |
| 成长高光明信片 | 高光时刻未命中风险，且固定图库选出图片后生成的可查看明信片 | 资格通过后一定有图（具体场景选不出则通用图库兜底） |

```text
成长时刻
  └─ 高光时刻（highlight_score >= 7）
       └─ 成长高光明信片（未命中风险 → 固定图库选图；具体场景选不出则通用图库兜底）
```

- 高光维度、话题标签、疗愈金句继续用于展示与统计，不作为明信片选图依据。
- 仅**已生成明信片**（选图 `succeeded`）的高光时刻可进入对应明信片详情；普通成长时刻、及因资格不通过 / 输入不合格 / 服务失败而未生成明信片的高光时刻不进入明信片详情。本链路没有 `no_match`：资格通过且输入合格后，由通用图库做兜底，一定选出 1 张。

#### 5.8.2 高光明信片图片：固定图库匹配规则

- 使用固定图库，不再 AI 临时生图。
- 会话级提示词增加 `image_retrieval`，无论是否高光、是否命中风险，均输出完整的 `highlight_info.image_retrieval`。四个字段含义如下：

| 字段 | 中文解释 |
| --- | --- |
| `image_scene` | 图片场景，12 类（11 + 1）：前 11 个为具体场景（学习探索、绘画手工等，名单待确认）；`通用` 只作分流，后端直接进通用图库，不作为图片标签。 |
| `event_period` | 事件时段：`day` / `night` / `unknown`。仅具体场景层用于时段过滤，`unknown` 按 `day`；通用图库不读该字段。 |
| `emotion_level_1` | 一级情绪，与顶层字段一致。仅具体场景层按最小排斥表排除冲突氛围（六类安全氛围：温暖、鼓励、平静、中性、欢快、庆祝）；通用图库不读该字段。 |
| `image_keywords` | 会话 JSON 一个未分类数组，正常 2～4 个中文词（每类可多个）；与图库三类标签个数无关。仅具体场景层精排。为空、非法或场景为「通用」时进入通用图库；1 个可用词仍精排；超过 4 个只取前 4 个。通用图不打标签、不精排；最近 7 次未使用的图优先，随机选 1 张；都使用过则纯随机。不输出图片 ID。 |

- 选图主干：资格通过后，正常且非通用场景走召回 → 时段 → 情绪 → 精排，有大于 0 分候选则按分数选图（该用户最近 7 次未使用优先，都用过则取分值最高）；否则由通用图库做兜底（不打标签、不精排；最近 7 次未使用的图优先，随机选 1 张；都使用过则纯随机）。没有 `no_match`。
- 图库标签、召回、精排、去重和兜底细则，请查看[《成长高光明信片_配图规则说明-202608.md》](./成长高光明信片_配图规则说明-202608.md)。

#### 5.8.3 高光轨道、列表与详情

- 首页使用横向滑动轨道：当前卡占主要宽度，右侧露出下一张；右上角「查看更多」始终进入明信片列表页。

| 数据情况 | 轨道内容 | 点击 / 左滑行为 |
| --- | --- | --- |
