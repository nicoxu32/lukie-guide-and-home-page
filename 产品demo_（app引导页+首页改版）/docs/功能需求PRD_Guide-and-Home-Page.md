# Lukie App 引导、首页与「我的」改版功能需求 PRD

版本：2026-09-07
用途：供研发、设计、测试实现本版能力。界面布局、动效及最终文案以设计稿 / 原型为准；本文约定功能边界、状态判断、数据口径和跳转规则。

## 1. 需求目标与范围

### 1.1 需求目标

本版围绕以下需求完成改版：

1. **前置引导**：新用户从启动 App 到进入首页的首次引导可完整走通，包含注册、设备激活和交接仪式等步骤。
2. **新手引导**：增加 7 个步骤的新手指引，并支持示例态首页模块讲解。
3. **首页**：完成头图、最近对话、使用指南推荐卡、今日总结、成长时刻和成长高光明信片等模块的展示与状态改版。
4. **「我的」**：收口一级入口，承载宝贝档案、系统设置、使用指南和帮助内容。
5. **逻辑调整**：高光判定纳入风险等级；成长高光明信片改为固定图库匹配；首页头图状态与陪伴文案改为后端配置化；今日总结改为 IP 日记动效及面向家长的汇报口吻；宝贝档案作为后续新会话的智能体上下文；新手引导已读按新手引导教程版本记录（普通 App 发版不弹），存储方式待定（客户端本机 / 后端按账号）；新增新明信片查收逻辑；成长时刻与明信片历史音频存储至自有 OSS。

本文约定各模块的产品边界、状态判断、数据口径和跳转规则；图库标签和选图细则沿用对应配图规则。

## 2. 需求 1：前置引导

### 2.1 首次引导主路径

未登录且未绑定的新用户，当次完整走通：

启动页 → 品牌欢迎页 → 家长 / 监护人身份确认 → 注册登录 → 设备联网（仅 Lukie）→ 6 位激活码 → 宝贝档案 → 交接仪式 → 新手指引 → 首页。

#### 2.1.1 谁可以进首页、中断怎么续

进首页只看两件事，**不记录做到第几页**：

1. 是否已注册登录
2. 已登录时，是否已绑定设备

两件事都满足才能进首页；**否则不能进首页**。

| 打开 App 时的状态 | 走哪段 | 能否进首页 |
| --- | --- | --- |
| 未登录 | 欢迎 → 家长身份确认 → 注册登录 | 否 |
| 已登录、未绑定 | 从绑定续：Lukie 先连接 WiFi 再 6 位激活码；iluki 直接激活码 | 否 |
| 已登录、已绑定 | 进入首页（再按 §3.1 判断要不要弹新手引导） | 是 |

因此：老用户升级本版、已登录且已绑定，跳过注册、WiFi、激活码、档案和交接仪式，直接进首页。杀进程后再打开，同样只按上表分流，不从杀掉的那一屏续。

**身份确认、交接、激活失败：**

- 家长身份确认只出现在未登录路径，不能跳过登录去首页；未确认 / 未登录都不进首页。
- 激活失败 = 仍未绑定，不能进首页，留在激活页重试，**不能跳过激活**。
- 宝贝档案、交接仪式只出现在「当次绑定成功后的完整主路径」里，不是进首页门槛。已绑定再打开不再播交接、不再强填档案；档案可之后在「我的」补填。当次走到档案 / 交接时杀进程，下次因已绑定而进首页，不补播未走完的档案 / 交接。

### 2.2 启动与欢迎

- 启动页使用 Logo。
- 品牌欢迎页使用慢动画展示。

### 2.3 注册、联网与激活

- iluki 与 Lukie 的注册登录分别对齐现网，本版不改登录协议。
- Lukie：账号注册成功后先进入连接 WiFi 页，再进入 6 位激活码页。
- iluki：无连接 WiFi 页，账号注册成功后直接进入 6 位激活码页。

### 2.4 宝贝档案（整合为上下文加入智能体提示词）

#### 2.4.1 填写与落库

- 全部字段均非必填。字段与原型一致，本版不扩：

| 界面 | 落库 | 注入给模型 | 空了怎么办 |
| --- | --- | --- | --- |
| 宝贝称呼 | 文本 | 称呼 | 不写该行，不编名字 |
| 宝贝生日 | 日期 | **年龄**（按该会话开始当天计算），不给具体生日 | 不写年龄、不猜岁数 |
| 宝贝性别 | 男孩 / 女孩 | 性别 + 代词（中文他 / 她，其他语言用对应代词） | 不写、不猜代词 |
| 喜欢什么 | 14 项多选 | 兴趣列表，顿号分隔 | 整行不出现 |

兴趣枚举：体育运动、科技发明、恐龙世界、交通机械、科学实验、宇宙太空、文学阅读、音乐节奏、动物自然、绘画手工、积木建造、益智游戏、角色扮演、美食烘焙。

- 一项都未填写时，「保存并继续」禁用；点击无效。
- 任意填写一项后，「保存并继续」可点；点击后保存已填内容并继续。
- 「先不填，和 Lukie 慢慢探索」始终可点；点击后不保存，直接进入下一步。
- 已保存内容必须落库，供「我的 - 宝贝档案」回显和再次编辑。空字段不要写成「未知 / 未填写」。

#### 2.4.2 注入哪段提示词、谁来拼

**提示词不会自己读库。** 模型只看到拼好的整段文字。读库、算年龄、拼接的，是新建智能体会话时的服务端。

现有「Lukie 全能伙伴」运行时提示词**原文不改**，只增加两处：① 模板里写死的使用规则；② 文末动态资料段 `## 眼前这个孩子`。完整提示词见[《智能体-对话聊天提示词_202609.md》](./智能体-对话聊天提示词_202609.md)。不注入日级或会话级洞察提示词。

| 端 | 做什么 |
| --- | --- |
| App | 档案页读写这 4 个字段；保存、回显、跳过不写。不在客户端拼提示词。 |
| 档案后端 | 按账号存这 4 项；供会话服务读取当前档案。 |
| 智能体会话 / 运行时提示词组装（现网把「Lukie 全能伙伴」塞进新会话的那条链路） | 新会话时取档案、转换、拼进模板。规则段可写死在模板；资料段只拼有值的行。 |
| 洞察 / 首页 / 选图 | 不为档案改。 |

流程：App 保存 → 档案落库 → 孩子新开对话 → 会话服务取当前档案 → 只留非空字段并换算年龄 / 代词 → 有值则拼上资料段再送给模型；全空或跳过则资料段不出现。这份提示词跟这次会话绑死；家长中途改档案，下一场新会话才换。不重跑历史洞察、不改写历史对话和已生成内容。

#### 2.4.3 提示词正文

完整「Lukie 全能伙伴」运行时提示词（含档案规则段与文末资料段模板）见[《智能体-对话聊天提示词_202609.md》](./智能体-对话聊天提示词_202609.md)。

- 固定规则写在「怎么说话与陪伴」中、「根据孩子的年龄和理解力调整表达」之前。
- 动态资料段 `## 眼前这个孩子` 拼在提示词末尾：至少有一个非空字段时追加，只输出有值的行；四个都空或跳过档案则整节不出现。

## 3. 需求 2：新手引导

### 3.1 新手引导：出现与已读

本版采用方案 A：简单方案（不区分完成、跳过和关闭，同一套新手引导教程只弹一次）。

- 仅在两种情况下出现：① App 下载后第一次打开；② 新 App **带了新的新手引导教程**后的第一次打开。
- **普通 App 更新不弹。** 修 bug、加功能、升版本号，只要新手引导教程没变，已读用户不再看到引导。
- 用户完整走完、点击「跳过」或点击右上角关闭，均记录为当前新手引导教程已读；同一套教程后续不再出现。
- 已读按**新手引导教程版本**记录，不按 App 版本号。只有新 App 里的教程相对已读教程发生了变化，才再弹一次。

#### 3.1.1 已读状态归属（待定，看技术侧方案）

产品规则已定，两种存储都要遵守：

- 完成、跳过、关闭写入**同一条**已读，不区分结果、不记录中断步骤。
- **按新手引导教程版本记录，不按 App 发版记录。** 同一套教程不再出现。普通 App 更新（教程没变）不弹；只有新 App 带了新的新手引导教程，才再弹一次。
- 读写失败**不阻断**退出引导、进入真实首页。

**存储落在哪边，本版不预设，由技术侧出方案后回写。** 两套都能满足上面的产品规则：

| 方案 | 怎么记 | 用户侧差异 |
| --- | --- | --- |
| A. 客户端本机 | 本机按新手引导教程版本记一条；后端不提供接口 | 卸载清数据、换设备会再弹；同账号多设备各记各的；本机已读后换账号也不再弹。实现简单，是这类引导的常见做法。 |
| B. 后端按账号 | 按 `账号 + 新手引导教程版本` 落库；客户端读写接口 | 卸载重装、换设备不再弹；换账号跟新账号走。多端一致，但本版要加接口。 |

与 §4.4 使用指南推荐卡无关：推荐卡关闭已定按账号落后端。本项定案后，同步回写 §1.2.2。

### 3.2 新手引导：展示和结束

- 底图使用包含全部首页模块的有数据示例态（不使用真实数据），保证用户能看到完整模块讲解。
- 共 7 步，顺序为：自我介绍 → 唤醒方式 → 使用指南 → 关注提醒 → 今日情绪分和今日总结 → 成长高光明信片 → 成长时刻。
- 每步配置对应的形象图；当前步骤的目标模块滚动至可见区域并高亮。具体文案以原型为准。@设计师
- 完成、跳过或关闭后，立即退出示例态并进入真实首页，不保留任何示例数据。

## 4. 需求 3：首页

首页按模块组合，不为每种状态单独建设一套页面。先按当天真实数据确定页面状态，再套用各模块规则。

### 4.1 首页状态判断

| 状态 | 条件 | 页面表现 |
| --- | --- | --- |
| 新手引导中 | 满足 3.1 的展示条件，且用户尚未结束当前引导 | 展示包含全部首页模块的有数据示例态并叠加新手引导；示例数据不落库；引导结束后进入真实首页对应状态 |
| 首日仅有明信片 | 第一次绑定设备后的首日，且当天无对话 | 展示预设初见明信片；隐藏今日情绪分与今日总结；状态时刻和成长时刻使用空置态 |
| 日常无对话 | 非首次绑定首日，且当天无对话 | 头图和对话入口使用空置态；隐藏今日情绪分与今日总结；明信片展示无数据卡和最近 7 张；成长时刻展示今日空置卡并默认展开历史 |
| 有数据 · 有高危 | 当天有对话，且**日级**风险判定命中（日级由当天各段会话汇总：`is_hit` 取 OR、`level` 取最高） | 所有有数据模块按规则展示，包含高危模块。**高危模块与明信片模块各看各的数据**：高危模块看日级汇总结果，明信片按每段会话各自的风险等级逐段判定。**当天命中高危不代表当天没有明信片**——只要还有其他未命中「高风险 / 紧急」的会话判为高光，照常出片 |
| 有数据 · 无高危 | 当天有对话且未命中高危 | 所有有数据模块按规则展示，不展示高危模块 |

### 4.2 首页头图（状态时刻 + Lukie 大头）

#### 4.2.1 展示规则

- 展示 Lukie 在线状态，口径与设备管理页一致。
- 右侧蓝色大头按分值档位（含空置档）10 个档位，匹配对应形象图；素材由设计提供。
- 当天无对话时，展示空置状态信息和空置大头。
- **产品目标：当天有对话，则应有 0–100 的 `daily_mood_score`。** 有对话却为 `null`，不是本版要设计的产品空态，属于日级结果与首页读取不同步，**继续由技术侧解决**：有对话时把同一份已落库日级结果（含分数）同步到头图、今日情绪分、今日总结。同步到位后，不应再出现「有对话、头图走空置、情绪分没数」。
- 同步完成前的头图兜底：若仍读到 `null`，头图（状态时刻文案 + 蓝色大头）单独走 `null` 空置档「等待今日心情」，不得把 `null` 当成 0–10 分；今日总结、成长高光明信片、成长时刻等其余有数据模块仍按有数据规则展示，不受头图空置影响。今日情绪分卡片见 §4.6，不为这种不同步单独做空置文案、不展示「—」、不藏卡。


#### 4.2.2 头图数据口径与文案规则

- `daily_mood_score` 由日级提示词产出，用于今日情绪分、今日总结和首页头图；`session_mood_score` 由会话级提示词产出，仅用于会话级洞察。
- 两者使用**同一套分值标尺**：九档有效分 + `null` 空置，以及同一套三个打分维度（情绪强度、持续时间、情绪走向）。区别只在数据范围——会话级看单段会话，日级看当天全部会话。日级不得另起区间，也不得把各段 `session_mood_score` 简单平均。本版头图只调整分段文案配置，分数仍由提示词按上述标尺产出。
- 提示词不再输出 `mood_state`、状态时刻档位和陪伴文案；后端根据 `daily_mood_score` 查询配置表，返回状态档位 ID、状态名、文案和对应大头素材信息。
- 首页头图读取的 `daily_mood_score` 范围为 `0–100`；为 `null` 时进入独立空置档「等待今日心情」，不属于 `0–10` 分。
- 后端按 `daily_mood_score` 命中的状态档位，从每档 5 条候选文案中随机选取 1 条；随机仅发生在分数更新时，结果与分值、状态一并落库，刷新或重复进入首页不重新随机。
- 状态名和陪伴文案通过配置表维护，使用 i18n 文案 key；客户端仅展示后端返回结果，不自行分档、随机或翻译。
- 方案 A–E 的文案全部进入候选池，不预先固定某一套方案；具体分值区间、状态名和候选文案见下方「5.2.3 状态时刻文案配置」。

- 当天无对话时不展示该入口。

- 点击「去查看」进入「我的 - 使用指南」网页版。

### 4.5 高危情绪

- 仅当天有对话且命中高危时展示。
- 判断、数据生产和卡片样式沿用现有规则。
- **日级风险是会话级的汇总**：日级 `risk_judgement.is_hit` 取当天所有会话的 OR，`level` 取其中最高等级。本模块展示的是这个**日级**结果，由日级提示词产出。**本版日级 `level` 仍只汇总为「高风险 / 需关注 / 空」，不补「紧急」**；首页高危模块按现网日级结果展示即可。会话级仍有「紧急」，只用于该段会话的高光判定（不出片），不要求日级首页高危卡单独识别「紧急」。
- **与成长高光明信片是两条独立链路，不要相互推导**。高危模块看日级汇总；出不出明信片看**每段会话各自**的会话级 `risk_judgement.level`，逐段判定：
  - 某段会话 `level` 为「高风险 / 紧急」→ 后端算出的 `has_highlight` 为 `false`，**这段会话不是高光时刻，只是一条普通的成长时刻**，照常留在成长时刻列表里，只是不出明信片（家长此时已收到风险提醒，不应同时推送轻量正向卡片）。「需关注」不影响出片。
  - **同一天其他未命中「高风险 / 紧急」的会话不受影响，照常成为高光并触发选图。** 因此「当天展示了高危模块 + 当天有高光卡」是**正常状态，不是冲突**，开发不要用日级 `is_hit` 去拦截当天的高光判定或选图。
- 明信片模块**不需要为风险做特殊处理**：只有当天一段高光都没产出时，才按「当天无高光时刻」展示（无数据卡 + 最近 7 张），和「当天没聊出高光」走的是同一条路径。详见 §4.8.1。

### 4.6 今日情绪分与今日总结

- 当天无对话时，两张卡片均不展示，直接从页面移除，不展示空卡。
- 当天有对话时，两张卡片均展示。今日情绪分展示已落库的 `daily_mood_score`（0–100）。有对话却分数为 `null` 不作为产品空态：不藏卡、不另写空置文案、不展示「—」、不把 `null` 打成 0 分；由技术侧把日级分数同步到首页后，卡片正常出分。今日总结字段、生成链路和数据口径沿用现网，仅调整面向家长的汇报口吻与呈现动效。
- 今日总结不再依赖图片库匹配具体对话场景：图片库无法覆盖用户多样化场景，改为 Lukie IP 动效卡片。
- 动效卡片采用日记视觉：以日记纸张 / 手写卡片作为背景，Lukie IP 伴随“打字”或“书写”动作，并根据情绪展示对应表情；今日总结内容随书写过程逐行呈现，全部内容呈现完毕后停止书写动作，保留陪伴式静态状态。
- 动效节奏以内容可读性为优先：若连续动作造成视觉干扰，减少动作频次或保留关键节点动效，不影响总结内容完整展示。
- IP 表情系统的落地粒度由 @设计师定，两种方案均可：
  - 细分方案：按 `daily_mood_score` 或今天的一级情绪映射 9 种情绪表情动画；
  - 基础方案：按平静 / 中性、正面、负面 3 类基础情绪配置表情动画。
- 逐行书写的具体表现、完成后的停笔姿态与静态回退视觉由 @设计师定；均可按设计效果落地，不影响上述功能逻辑。
- 提示词口吻调整为 Lukie 面向家长汇报的口吻：以第三人称描述孩子当天的状态与值得关注的变化，温和、具体、可理解，避免直接对孩子说教；不改变原有总结字段和生成链路。
- 话题标签支持点击，用气泡展示完整标签文字，格式为 `#标签名`。

**今日总结动效数据与状态：**

- 日级提示词输出今日总结文本、`emotion_level_1` 与 `daily_mood_score`，作为 IP 表情和动效配置的输入。
- 后端根据情绪映射返回 IP 表情状态与动效配置；客户端按已落库的总结文本逐行播放，刷新和重试不重新随机表情或改写内容。
- 动效播放失败时回退为静态日记卡片，仍完整展示总结文本；不因动效资源异常隐藏今日总结。


### 4.7 成长时刻（原时光流）

- 内容展示沿用现有成长时刻结构；标题、总结、标签等由会话级提示词产出。
- 已生成成长高光明信片的成长时刻也必须保留在成长时刻列表中。
- 仅高光时刻可进入对应明信片详情；普通成长时刻不可点击（没有详情页），但仍可播放音频。高光判定与选图结果为两条独立状态：选图进行中图片区加载中，`succeeded` 展示图片，图库缺口展示占位图，输入不合格或选图服务失败展示无图失败态；均不改变高光资格或详情可达性。
- 成长时刻列表需支持播放 1 个月以前的历史音频：接口返回超维 OSS 音频地址与播放时长；有音频时展示播放控件，无音频时仅隐藏播放控件，不影响其他内容展示。

**当天有成长时刻**：默认仅展示今日内容；末尾展示「上滑，继续浏览过往成长时刻」；上滑后按现网规则分页加载历史，减少请求压力。
**当天无成长时刻**：展示「今日空置无数据卡 + 过往成长时刻」，且过往内容默认展开，无需上滑操作。

### 4.8 成长高光明信片（图库匹配）

#### 4.8.1 概念与数据边界

| 名称 | 定义 | 是否每段会话都有 |
| --- | --- | --- |
| 成长时刻 | 原时光流卡片，包含标题、总结、原话、音频等现有内容 | 有会话即可有 |
| 高光时刻 | `has_highlight = true` 的成长时刻，即 `highlight_score >= 7` **且** 风险等级不是「高风险 / 紧急」。**该字段由后端计算，不再由提示词输出** | 分数达标且风险等级允许时有 |
| 成长高光明信片 | 高光时刻对应的可查看明信片详情，图片为固定图库的选图结果。高光资格与图片选取相互独立。 | 是高光即有详情；进行中图片区加载中，选图成功展示图片，图库缺口展示占位图，选图失败展示无图失败态 |

```text
成长时刻
  └─ 高光时刻（highlight_score >= 7 且风险等级 ∉ {高风险, 紧急}）
       └─ 成长高光明信片详情（固定图库选图；结果只影响图片状态，不影响高光资格或详情可达性）
```

- 高光维度、主题、话题标签、疗愈金句继续用于展示与统计；其中 `dimension_id` 与 `highlight_theme`（主题名）同时作为明信片选图的硬召回条件，`highlight_theme_id` 只用于区段校验、不参与查询。
- **会话洞察结果一次性产出，同一段会话不重复分析。** 分数、风险等级、高光维度、主题、归属场景，以及后端据此算出的 `has_highlight` 和选中的图片，都随首次分析结果落库固定，之后不再重算，也不存在「事后改判」——不会出现今天是高光、明天变成不是高光的情况。
  > 之所以定成不重跑：LLM 对同一段会话重新分析时，输出的措辞会有差异（大意相同，但标题、总结的具体说法会变）。重跑会让家长已经看到的卡片内容和明信片发生无意义的变化，因此一律以首次落库结果为准。客户端刷新、重试都只读已落库结果。
- **新旧数据边界**：新规则仅用于上线后新产生的会话与明信片。旧数据库中已生成的明信片保留原高光判定、图片关联和现有 OSS 地址，继续按原结果展示；不重跑提示词、不重算 `has_highlight`、不重新选图，也不迁移到新固定图库。旧记录缺少 `highlight_theme`、`content_scene` 或新选图状态时，不视为异常，不影响历史列表和详情查看。
- **历史高光时刻的图片：只认落库的 OSS 地址，拿到什么图就展示什么图。** 选图成功后，业务库在该高光 / 明信片记录上写入当时选中素材的 `oss_url`。首页、列表、详情都只读这条地址取图，**不再回查图库标签、不重新选图**。本版不要求为历史画面单独做 `asset_version` 或文件快照；选图数据模型是否再拆字段属于后端实现，不阻塞本版产品口径。
- **素材替换后，历史是否跟着变（产品规则）：**
  - 运营在**同一 `oss_url` 上覆盖文件**（同路径替换）时，历史明信片会跟着变成新图。本版接受这一结果。
  - 若希望历史画面不变、只给以后的新高光用新图：必须上传为**新文件 / 新 `oss_url`** 并给新素材打标；旧记录继续指向旧地址。
  - 只改标签、不换文件：不影响任何已落库历史明信片，只影响之后的新选图。
  - 素材下架或地址失效：已写入历史记录的 `oss_url` 仍按该地址取图；取不到时走客户端占位图，不改写已落库结果、不补选。
- 高光时刻均进入高光时刻列表并可打开对应明信片详情；普通成长时刻不进入该列表也不可进入详情。选图任务排队或进行中时，卡照常出现，标题 / 时间 / 文案照常，**仅图片区**为明信片轮廓 + 轻转圈（不写「生成中」，本版是图库匹配不是生图），不空白、不用占位图顶加载；可点进详情，详情图片区同样加载中。选图 `succeeded` 时展示关联图片；硬召回为空时展示占位图并进补图清单；输入不合格或选图服务失败时展示无图失败态。上述图片状态均不改变 `has_highlight`，也不影响详情可达性。

#### 4.8.2 高光明信片图片：固定图库匹配规则

- 使用固定图库，不再 AI 临时生图。
- **提示词只出数据，高光资格由后端判定。** 会话级提示词负责产出 `highlight_score`、`risk_judgement`，以及 `highlight_info` 下**平铺**的 `dimension_id`、`highlight_theme`（含 `highlight_theme_id`）、`content_scene` 三个选图字段，不再包 `image_retrieval` 一层，无论分数高低、是否命中风险都必须输出。
- 后端拿到结果后按 `highlight_score >= 7 且 risk_judgement.level ∉ {高风险, 紧急}` 计算 `has_highlight`；成立时创建选图任务并持久化 `image_selection_status`。**提示词不输出 `has_highlight`**，避免 LLM 为了影响高光判定而调整分数或风险等级。

| 字段 | 中文解释 |
| --- | --- |
| `dimension_id` | 高光维度 1~6，单选。**硬召回条件之一。** |
| `highlight_theme` | 43 个主题之一，与配图规则 §2 主数据表逐字一致，单选。**硬召回条件之一**；同时输出 `highlight_theme_id`(1~43) 供区段校验。 |
| `content_scene` | 归属场景，只能是学习探索、艺术创作、阅读故事、游戏娱乐、运动体能、动物自然、家庭陪伴、朋友社交、`unknown`。**按高光片段所在的那几轮对话判定，不看整段会话里哪个话题聊得最多**；多场景并列或无法判断时输出 `unknown`。用于在硬召回结果内收窄，有则用、无则回退，不阻断出图。 |

- 选图主干：判定为高光后，后端用 `dimension_id` + `highlight_theme` 同时命中图片标签做硬召回（池 A），再用 `content_scene` 收窄（池 B，未命中或 `unknown` 时回退池 A），优先使用该账号（`user_id`）最近 7 次未使用的候选图；候选图全部用过时，选择最久未使用的图，并列时再随机；所有随机以 `session_id` 为种子并锁定结果。**不存在「主题映射视觉方向」这一步。**
- 字段非法时的处理：`dimension_id` 与主题所属维度不一致、或 `highlight_theme_id` 与主题名对不上时，**一律以主题名为准回正**并照常选图；只有主题名不在 43 个里才标记选图输入非法、展示无图失败态。`content_scene` 非法归一为 `unknown`，不影响选图。以上均不改变已计算的高光资格。
- **运营覆盖率是本方案的前置依赖**：本版不设独立通用兜底图库，需保证每个已上线主题至少有 1 张图打上该主题（靠一图多主题摊薄）。硬召回为空属于图库缺口异常，走占位图并进补图清单。
- 图库标签、召回、去重和兜底细则，请查看[《成长高光明信片_配图规则说明-v2-维度主题匹配-202609.md》](./成长高光明信片_配图规则说明-v2-维度主题匹配-202609.md)。
- 选图主轴为「**高光维度 + 高光主题（硬召回） → 归属场景（收窄，可回退） → 最近 7 次未使用优先 → 最久未使用兜底（并列随机）**」；完整字段、标签和召回细则见专项配图规则文档。

#### 4.8.3 高光明信片的滑动交互轨道、高光时刻列表与详情

- 首页使用横向滑动轨道：当前卡占主要宽度，右侧露出下一张；右上角「查看更多」始终进入明信片列表页。账号仍有未查收明信片时，首页明信片区域先走 §4.8.4 查收仪式，不提前出图；查收完成后再按本表展示与点击。

| 数据情况 | 轨道内容 | 点击 / 左滑行为 |
| --- | --- | --- |
| 首次绑定且仅有预设初见明信片 | 1 张「宝贝和 Lukie 第一次见面啦」 | 点击或左滑进入列表页 |
| 当天无高光时刻 | 1 张无数据卡 + 最近 7 张高光卡 | 无数据卡进入列表；左滑浏览历史，末张再左滑进入列表 |
| 当天有高光时刻 | 最近 7 张高光卡 | 点击任意卡进入对应详情；末张再左滑进入列表 |

- 无音频时不展示播放控件，图片状态、标题和文案仍展示；选图进行中图片区加载中；选图服务失败或输入不合格时，图片区域展示无图失败态，不用无关默认图替代。
- 首页轨道只展示 `has_highlight = true` 的高光卡；每张卡按其选图状态展示加载中、真实图片、图库缺口占位图或无图失败态，选图失败或进行中的高光卡仍可点击进入详情。
- 首日预设卡和无数据卡在首页点击时均进入列表，不直接进入详情。
- 高光时刻列表页仅展示全部历史高光时刻，按会话时间倒序展示，不限制数量；无论选图状态，点击任意卡均进入对应明信片详情。视觉和网格以设计稿为准。
- 明信片详情页：选图进行中时图片区加载中，标题和文案照常；选图成功后展示该记录已落库的 `oss_url` 对应图片（OSS 上当前是什么文件就展示什么图），以及该会话提示词首次产出并落库的标题、总结、情绪标签和会话时间；字段内容与成长时刻保持一致，不重复生成或改写、不重新选图。
- 当天已有其他首页数据但当天无高光时刻时，明信片模块仍需展示无数据卡和历史 7 张，不可隐藏整个模块。

#### 4.8.4 明信片查收仪式（新增）

查收是账号上的**收件箱未读**，不是每张明信片各自拆封。一次查收拆完当前全部未读，不限今天还是更早产生的。

**什么算未读**

- 上线后新产生、且已有可展示图片（选图 `succeeded` 并写出 `oss_url`）的明信片，其**图片就绪时间**晚于该账号上次「已看过收件箱」的时间，即为未读。含会话高光卡，也含首日预设「第一次见面」——要走查收就全部走同一套。未读看图片就绪时间，不看会话产生时间。
- 上线前已存在的历史明信片一律视为已看过，不进仪式，直接出图。
- 选图排队 / 进行中还没有可拆封的图，不计入未读、不演仪式。
- 选图服务失败或输入不合格的高光没有可拆封图片，不计入未读、不进仪式；列表与详情直接展示无图失败态，仍可查看高光内容。
- 本版图库按运营覆盖率前置，查收侧不考虑「图库缺口占位图」这一分支。

**各入口怎么展示**

- **仅首页**明信片区域：有未读真图时先展示 Lukie 递送未拆封明信片的动态效果，不提前出图。点击「查收新明信片」后播一次拆信动效，**一次拆完当前全部未读**（多封不逐张拆），动效完成后再按 §4.8.3 展示轨道。允许跳过动效，但必须先完成已读写入。
- **进首页时**已有未读真图 → 演一次仪式。人已经停在首页、该卡正在加载中 → 图到了就原地换成真图，**不中途补播拆封**。
- **列表、详情始终直接出图**（进行中则图片区加载中），不播递送 / 拆封特效，也不展示未拆封卡。从成长时刻点进高光详情同样如此。
- 递送或拆封动效加载失败时，首页回退为可点击的静态未拆封卡；点过后进入已查收，按 §4.8.3 出图。

**什么时候记「已看过收件箱」**

以下任一动作都将当前全部未读一次性记为已查收（按账号落库，多端一致）：

1. 在首页完成查收仪式（含跳过动效、点静态未拆封卡）。
2. 进入明信片列表页。
3. 进入任意一张明信片详情（含从成长时刻进入）。

因此：先去了列表或详情再回首页，首页不再演仪式，直接出图。之后若又产生新的明信片，未读重新出现，首页再演一次（仍是一次拆完当时全部未读）。

**记录方式（产品口径，不是接口方案）**

不要给每张明信片单独记「拆没拆」。按账号记一条收件箱已读时间即可：未读 = 上线后、选图已成功写出 `oss_url`、图片就绪时间晚于该时间的明信片。上述 3 个动作把已读时间更新到当前。与 §4.4 推荐卡关闭一样，必须按账号落后端，不能只记在本机——列表 / 详情看过也要让首页和其他设备不再演仪式。
